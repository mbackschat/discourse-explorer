# Sample Forum — Provenance and Re-Generation Costs

This doc records how the `sample/` subtree's code and committed cache file came into being, and what triggers re-generation. Read before changing anything that might invalidate the cache, or before estimating cost for a new seed/scale combination.

## Three distinct generation paths

The subtree contains three kinds of generated artifacts with different cost profiles. Don't conflate them.

### Python scripts — everything under `sample/seed/*.py`, `sample/seed/blocklist.txt`, all `sample/tests/*.py`

Generated by **Claude Code subagents** delegated to with `Agent(subagent_type: "general-purpose")` — those agents run on **Sonnet** by default.

The scripts are on disk. They are NOT re-generated when you re-run the test suite, the smoke test, or any other day-to-day operation. Re-running existing code costs nothing in agent tokens.

The only path that re-spends Claude tokens is **further development** — Sit 12 onward, or revisions to a sit. Existing files don't decay or auto-regenerate.

### JSON cache file — `sample/seed/content/cache/crown-of-brine-openai-seed42-tiny.json`

Generated by **OpenAI**, model `gpt-4.1-mini` — the project's default extraction model (mirrored from `discourse_explorer.config.OPENAI_EXTRACTION_MODEL`). The Sit 11 smoke test used this default because no `EXTRACTION_MODEL` env var was set at run time.

- 112 chat-completion calls (one per generated post)
- ~366 seconds wall-clock for the cold cache
- ~0.11 seconds wall-clock for the warm cache (subsequent runs hit the cache, no LLM calls)
- Estimated $0.05–$0.10 total at the model's pricing tier as of writing — recheck https://openai.com/api/pricing for current numbers

The file is committed to git. Anyone cloning the repo and running the smoke test against the same `(seed=42, scale=tiny)` regenerates the same forum **for free** — cache hits short-circuit OpenAI entirely.

### Visualizer caches — `sample/fixtures/seed42-tiny/visualize/cache/*.json`

Two files under the fixture's `visualize/cache/` directory, generated at build time when `discourse-explorer visualize` runs against the fixture:

- **`layout.json`** (~20 KB) — force-directed graph layout coordinates from networkx. Pure offline, no LLM, no network. Regenerates in seconds; safe to delete and re-build anywhere.
- **`rel-clusters.json`** (~3.3 MB) — relationship-keyword clustering used to label the visualizer's edge legend. Auto-selects between two modes by `OPENAI_API_KEY` presence:
  - **`llm-cluster` mode (OpenAI configured)** — embeds every unique keyword via `text-embedding-3-large` (3072d), k-means at `cache_k=50`, then Ward merge to the requested display count. The committed cache is in this mode. Cost on the tiny corpus: a few cents (≈100 unique keywords × one batched embedding call).
  - **`token-cluster` mode (no OpenAI)** — string-token similarity, fully offline, free. Output is structurally different — `mode: "token-cluster"`, no embeddings — but loads and renders identically downstream.

**Reproducibility implication.** Regenerating `rel-clusters.json` on a no-key machine produces a `token-cluster` file that won't byte-match the committed `llm-cluster` copy. `test_fixture.py` passes either way (it checks for non-empty output, not byte equality), but a maintainer who deletes the cache and re-runs without an OpenAI key gets a different file. To recover byte-equality, set `OPENAI_API_KEY` and `OPENAI_EMBED_MODEL=text-embedding-3-large` (matching the committed cache header), then re-run `discourse-explorer visualize sample/fixtures/seed42-tiny`.

Algorithm + cache schemas for both modes: [`docs/analysis/rel-clusters-algorithm.md`](../../../docs/analysis/rel-clusters-algorithm.md) at the project root.

## When the cache needs re-baking

The cache filename encodes the cache key: `<product>-<provider>-seed<N>-<scale>.json`. Changing any dimension invalidates the cache by routing to a different filename. Implicit dimensions (model name, universe content) invalidate without renaming the file — those are the foot-guns to watch.

| If you change…                                  | Tiny scale  | Medium scale | Notes                                                  |
|-------------------------------------------------|-------------|--------------|--------------------------------------------------------|
| `--seed` (e.g. 42 → 99)                         | ~$0.05–0.10 | ~$1–2        | Most common variation                                  |
| `--scale` (tiny → medium)                       | n/a         | ~$1–2        | First time at a new scale                              |
| Provider (OpenAI → Ollama)                      | free        | free         | Local model; trades cost for time/quality              |
| `EXTRACTION_MODEL` (e.g. → `gpt-4o`)            | ~$0.50–1.00 | ~$10–20      | `gpt-4o` is ~10× the cost; cache filename unchanged    |
| Anything in `crown_of_brine.py` (renames, lore vocab edits) | ~$0.05–0.10 | ~$1–2        | Universe drift; same provider+seed but different prompts |

Numbers are coarse estimates from the Sit 11 smoke test extrapolated by post count. Re-measure when OpenAI pricing or model defaults change.

## Model choice rationale

### Body generation — `gpt-4.1-mini`

The project's default; the same model that drives entity extraction in the parent project. Picked because:

- It's already configured everywhere else (no special-casing needed for `sample/`)
- For demo bodies (background texture, not the headline), the quality is sufficient
- ~$0.05 per 100 posts at tiny scale is well-amortized over future runs — the cache means you pay it once

Tradeoffs at the alternatives:

- **`gpt-4.1-nano` / older `gpt-4o-mini`** — cheaper but blander bodies; not worth the saved pennies for a one-time bake
- **`gpt-4o`** — ~10× cost, noticeably better narrative coherence; worth it only if the demo is itself the headline
- **`gpt-4.1`** — even higher cost; overkill for fan-forum post bodies

To switch, set `EXTRACTION_MODEL=<name>` in `.env`, delete the existing cache file, and re-run the smoke test once.

### Code generation — Claude Sonnet (default for `general-purpose` subagents)

Sonnet handled all eleven sits without trouble. Opus would have been overkill for mechanical generator code. The orchestration layer (the conversation that drove this work) ran on Opus per session config — that cost lives in the parent conversation's token bill, not in the committed artifacts.

## How to re-bake the cache

If a review uncovers a problem (e.g. you rename something in `crown_of_brine.py`, switch to a better model, or want a different seed):

```bash
# 1. Identify the cache file you're about to invalidate
ls sample/seed/content/cache/

# 2. Delete it — git remembers the previous version if you ever need it back
rm sample/seed/content/cache/crown-of-brine-openai-seed42-tiny.json

# 3. Re-run the smoke test (uses .env at project root for OPENAI_API_KEY)
uv run --env-file=/path/to/project/.env python -m sample.seed init \
    --seed 42 --scale tiny --output /tmp/sample-42.json

# 4. Spot-check the new bodies
jq -r 'to_entries[0:5] | .[] | "=== " + .key + " ===\n" + .value' \
    sample/seed/content/cache/crown-of-brine-openai-seed42-tiny.json | head -60

# 5. Commit
git add sample/seed/content/cache/
git commit -m "Re-bake sample cache after <change description>"
```

Run from the worktree root (or the main checkout, post-merge) — not from inside `sample/` — because `--env-file` resolves relative to the cwd.

## What is intentionally NOT cached

- Categories, tags, users, timeline, topic structure, post structure (reply trees, accepted-solution flags, cross-references) — these are **deterministic from the seed alone** and re-derive in milliseconds. No need to cache; no cost to re-generate.
- Topic titles — generated from templates and lore vocab, deterministic per seed. Free to re-generate.
- Only **post bodies** require an LLM call, hence only those are cached.

This is by design: cache only what's expensive to re-derive. Everything else is structural and the per-component salted RNG (`spec.rng("categories")`, etc.) makes re-derivation reproducible.
